# Редакция v2: один промпт на сеть каналов + двойная проверка GPT и Claude

## Как работает

1. Сборщик собирает по одной свежей ссылке с каждого источника и одним коротким запросом оценивает все заголовки сразу: реклама, объявления о продаже, старые пресс-релизы и чужие темы отсеиваются (статус `prefilter_skip`, в ленте не показывается), остальные сортируются по важности, в работу идут лучшие. Новости без даты с прошлым годом в заголовке отсеиваются без запроса. Сборщик находит новость. До подготовки медиа и вызова нейросетей идёт дешёвая проверка на дубль недавно опубликованного поста: явный повтор сразу уходит в «Дубль сюжета» без расходов на медиа и редакцию. Затем готовится медиа (как раньше).
2. **Автор** (OpenAI, `OPENAI_MODEL`) получает системный промпт из `prompts/chto-tam.md`: общие правила и профиль только этого канала. Автор может пропустить новость (`status: skip`): низкая важность, старая, дубль в сети, реклама, запрет по закону. Пропущенная новость сохраняется со статусом `editorial_skip`.
3. **Проверка**: тот же промпт в роли `checker` уходит параллельно в OpenAI и в Anthropic Claude (`ANTHROPIC_MODEL`). Каждый сверяет цифры, даты и имена с источниками, юридические пометки и запреты профиля. Побеждает самый строгий вердикт.
4. `fix` — пост уходит автору с замечаниями (`fix_notes`), не больше `EDITORIAL_V2_MAX_FIX_ROUNDS` раз.
5. Итог:
   - `pass` — пост в очереди с `qcStatus: pass`, его возьмёт расписание;
   - `reject`, ошибки после всех исправлений, дословное совпадение с источником или недоступна одна из нейросетей — пост в очереди с `qcStatus: hold`. Сам он не опубликуется, причина видна в карточке.
6. Склейка нескольких источников в одну историю идёт через тот же цикл «автор + две проверки» (`merge_check`).

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `EDITORIAL_V2_ENABLED` | `true` | `false` — мгновенный откат на старую схему рерайт + QC |
| `ANTHROPIC_API_KEY` | — | ключ Claude; без него проверяет только GPT |
| `ANTHROPIC_MODEL` | `claude-sonnet-5-5` | модель Claude для проверки |
| `EDITORIAL_V2_MAX_FIX_ROUNDS` | `2` | сколько раз автор может исправлять пост |
| `EDITORIAL_V2_REQUIRE_ALL_CHECKERS` | `true` | если одна из нейросетей не ответила, пост ждёт ручной проверки |
| `STORY_PRECHECK_ENABLED` | `true` | проверка на дубль до медиа и нейросетей; `false` — только после написания поста |
| `HEADLINE_PREFILTER_ENABLED` | `true` | отбор заголовков до медиа и редакции |
| `SOURCE_AUTO_PAUSE_ENABLED` | `true` | автоотключение источника: 10 отсеянных новостей подряд или 12 ошибок загрузки подряд; в группе остаётся минимум 4 источника; ручное включение сбрасывает счётчики |
| `SOURCES_MIN_ACTIVE` | `40` | минимум активных источников на канал (меняется и в админке, раздел «Источники»); недостающие подбираются из резерва, затем AI-поиском, каждый проверяется загрузкой ленты; удалённые вручную сайты не возвращаются |
| `SOURCE_REPLENISH_INTERVAL_MINUTES` | `120` | как часто можно добавлять источники (не больше 5 за раз) |
| `POST_RATING_MIN_AUTO` | `50` | ниже порога пост «запасной»: выходит, только если в слот нет поста лучше; среди готовых первым выходит пост с более высоким рейтингом |
| `POST_RATING_DROP_BELOW` | `35` | ниже — пост убирается из очереди автоматически (статус `auto_rejected`); так же убираются посты, отклонённые проверкой (reject, ошибки не исправлены, совпадение с источником). Ручного подтверждения нет |
| `DIGEST_ENABLED` | `true` | вечерний дайджест «Главное за день» (`DIGEST_EVENING_TIME`, 21:15 МСК, от 4 постов за день) и воскресный «Топ недели» (`DIGEST_SUNDAY_TIME`, 20:15, лучшие по просмотрам); проходит ту же двойную проверку |
| `DAILY_REPORT_ENABLED` | `true` | итоги дня владельцу в личку бота в `DAILY_REPORT_TIME` (22:50 МСК); чат находится сам после /start боту или задаётся `TELEGRAM_ALERT_CHAT_ID`; кнопка «📊 Отчёт в Telegram» на странице сборщика |
| `SCHEDULER_SLOT_WINDOW_MINUTES` | `10` | окно, в течение которого слот расписания ещё можно выполнить |
| `CROSS_CHANNEL_DEDUPE_ENABLED` | `true` | одна и та же статья (адрес без utm и т. п. или хеш текста), уже стоящая в очереди, обрабатываемая или опубликованная другим каналом сети, не берётся повторно; проверка при сборе и перед публикацией; `false` — прежнее поведение (свой угол в каждом канале решает автор) |
| `CROSS_CHANNEL_DEDUPE_HOURS` | `48` | окно этой проверки |
| `SKIP_RETRY_MAX` | `3` | сколько раз пробуется ссылка при временной ошибке (загрузка страницы, сбой нейросети, запись в БД), потом она считается просмотренной |
| `EXTRA_LINKS_PER_SOURCE` | `3` | после непригодной ссылки (старая, короткая, недоступна) в том же запуске открываются следующие непросмотренные ссылки источника |
| `UNDATED_ARTICLE_MAX_AGE_HOURS` | `12` | сколько живёт в очереди пост по статье без даты |

Свежесть задаётся профилем канала: 24 часа, для `science`, `world`, `home`, `food` — 72 часа (лимиты `ARTICLE_MAX_AGE_HOURS`, `DYNAMIC_SLOT_MAX_AGE_HOURS`, `QUEUE_MAX_AGE_HOURS` умножаются на 1 или 3). Время без часового пояса на сайтах `.ru/.su/.рф` читается как московское.

## Каналы

Профиль канала определяется полем `channelId` кабинета. Для `ai-main` это `ai`, для `chtotamtachki` — `auto`; для остальных профиль угадывается по названию. Явно задать профиль:

```
POST /api/workspaces/update  {"id": "<кабинет>", "channelId": "crypto"}
```

Допустимые значения: `ai auto money tech games kino science sport world stars travel shopping home food business crypto`.

## Реестр иноагентов и запрещённых организаций

```
GET  /api/editorial/registry
POST /api/editorial/registry  {"foreign_agents": ["…"], "banned_orgs": ["…"]}
```

Хранится в `/data/editorial-registry.json`. В модель уходят только те имена, которые встречаются в тексте источников.

## Диагностика

- `GET /api/editorial/status` — включена ли редакция, какие нейросети проверяют, последние вердикты.
- Админка → «Подключения» → «Редакция v2 (GPT + Claude)».
- В карточке новости: `editorialV2` — вердикт, раунды исправлений, ответ каждой нейросети, ошибки.

## Тесты

```
npm run test:editorial
```

Офлайн-тесты с подменёнными OpenAI и Anthropic: разбор промпта, сборка под канал, вердикты, цикл исправлений, отказ проверяющей нейросети, HTTP-запросы к обоим API.

## Обучение на аудитории

Раз в час система читает публичную страницу канала (t.me/s/…), сопоставляет просмотры и реакции с опубликованными постами и считает, какие форматы, заходы, источники, темы и часы выхода работают лучше среднего. Автор получает `format_stats`, `hook_stats`, `best_posts` и отметку `audience` у последних постов; очередь получает бонус обучения. Лог: `EDITORIAL_LEARNING`.
